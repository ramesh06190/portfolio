Accessible components

Patterns that show up in almost every government and healthcare application, built from scratch with vanilla JavaScript and the site's design tokens. Each one follows the WAI-ARIA Authoring Practices and is covered by Playwright keyboard tests.

Components

  • Sortable data table with pagination
  • Autocomplete combobox
  • Memorable date input
  • Multi-step form

Sortable data table with pagination

Sort buttons sit inside the column headers, and the sorted header gets aria-sort. The first cell of each row is a row header. A status line announces the sort and range after each change. Previous and Next use aria-disabled instead of disabled so they keep focus at the ends of the list.

    Autocomplete combobox

    Focus never leaves the input. Arrow keys move a highlight that is exposed with aria-activedescendant, Enter picks an option, Escape closes the list and a second Escape clears it. The number of matches is announced after a short pause so it does not talk over typing.

    Start typing, then use the up and down arrow keys to choose

      Memorable date input

      For dates people already know, like a date of birth, three labeled number fields are easier than a calendar widget for keyboard, screen reader and voice control users. This is the pattern used by GOV.UK and USWDS. Errors name the missing part and only mark the fields that are wrong.

        Multi-step form

        Each step is checked before moving on, and focus goes to the new step heading so screen reader users know the page changed. The progress list marks the current step with aria-current="step" and says "Completed" in text, not only with a checkmark. The last step lets people review and change answers before they submit. It reuses the combobox and date input from above.
